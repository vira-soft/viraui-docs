Menu opens a list of actions or choices from a trigger click (or equivalent activation). Portal mounting, collision-aware positioning, typeahead, and roving keyboard focus ship with the compound — compose `Menu.Trigger` with `Menu.Popup` and the item parts you need.

Plain commands use `Menu.Item`; linked destinations use `Menu.LinkItem`; exclusive picks use `Menu.RadioGroup` with `Menu.RadioItem`; persistent toggles use `Menu.CheckboxItem`. Groups, separators, and nested `Menu.Submenu` trees cover denser toolbars. Triggers accept any control through `render`, including custom chrome such as a [Surface](/components/layout/surface) account chip. Do not wrap Menu in [Popover](/components/overlays/popover) — Menu already owns the floating surface contract.

---

## When to use

- A short list of commands from a button, icon, or custom chip (Edit, Duplicate, Archive)
- Sort or view choices that stay selected while the menu is open
- Nested command trees or rows with destructive sentiment

## When not to use

- A richer panel with title, description, or form controls → [Popover](/components/overlays/popover)
- A brief read-only hint on hover or focus → [Tooltip](/components/overlays/tooltip)
- A task that should block the page → [Dialog](/components/dialogs/dialog)
- A closed form field that shows the current value in a trigger → [Select](/components/inputs/select)

## Common examples

### Separated commands

A compact action menu with a separator between primary and secondary commands is the default pattern. Static header content may sit inside `Menu.Popup` beside items when it stays non-interactive so roving focus remains on menu rows.

<PreviewSlot label="Menu preview" />

```tsx
import { Button, Menu } from '@viraui/react';

<Menu>
  <Menu.Trigger render={<Button>Actions</Button>} />
  <Menu.Popup>
    <Menu.Item>Edit</Menu.Item>
    <Menu.Item>Duplicate</Menu.Item>
    <Menu.Separator />
    <Menu.Item>Archive</Menu.Item>
  </Menu.Popup>
</Menu>
```

### Exclusive choices

Use `Menu.RadioGroup` with `Menu.RadioItem` when the open menu should show which sort or view is active. Match toolbar button style to neighbors.

```tsx
import { Button, Menu } from '@viraui/react';

<Menu>
  <Menu.Trigger render={<Button variant="secondary">Sort</Button>} />
  <Menu.Popup>
    <Menu.RadioGroup defaultValue="asc" label="Order">
      <Menu.RadioItem value="asc">Ascending</Menu.RadioItem>
      <Menu.RadioItem value="desc">Descending</Menu.RadioItem>
    </Menu.RadioGroup>
  </Menu.Popup>
</Menu>
```

Detached triggers share one menu through `Menu.createHandle()` when the open control sits outside the root tree.
