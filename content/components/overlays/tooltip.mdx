Tooltip shows a short hint when someone hovers or focuses a trigger — never the only place critical information lives. Wrap the app once in `Tooltip.Provider` at the root (same overlay shell as [Setup](/get-started/setup)) so open and close delays stay consistent across every tooltip on the page. Each instance pairs `Tooltip.Trigger` with `Tooltip.Content`; the trigger accepts any control through `render`, including [IconButton](/components/actions/icon-button) with an `aria-label` when the glyph alone would be ambiguous.

Content is brief — a [Text](/components/typography/text) node or a short phrase. For icon-only controls, repeat the accessible name in the tooltip so sighted hover matches what screen readers hear. Detached triggers and multiple triggers sharing one content surface use `Tooltip.createHandle()`; payload render props swap copy when the active trigger changes. Prefer [Popover](/components/overlays/popover) when the surface needs interaction, a title, or dismiss controls — tooltips are read-only hints.

## Common examples

A labeled button with matching hint text is the baseline pattern.

<PreviewSlot label="Tooltip preview" />

```text tab="Button tooltip"
Add a tooltip on the Bold button that repeats the label Bold. Use zero delay only in this demo.
```

```tsx
import { Button, Text, Tooltip } from '@viraui/react';

<Tooltip.Provider>
  <Tooltip>
    <Tooltip.Trigger render={<Button>Bold</Button>} />
    <Tooltip.Content>
      <Text>Bold</Text>
    </Tooltip.Content>
  </Tooltip>
</Tooltip.Provider>
```
