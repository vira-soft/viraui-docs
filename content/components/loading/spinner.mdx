Spinner is a compact animated indicator for short waits where reserving a full skeleton layout would be heavier than the task. Decorative spinners inside buttons or beside labels can stay `aria-hidden` when surrounding copy already conveys the state. Prefer the control's own `loading` prop on [Button](/components/actions/button) or [IconButton](/components/actions/icon-button) rather than nesting a manual Spinner.

When the spinner is the primary status signal, pair it with visible text that names the work, or wrap it in an element with `role="status"` and an accessible name. Spinners alone do not explain what is loading. For progress along a track, use [LinearProgress](/components/loading/linear-progress); for layout placeholders, use [Skeleton](/components/loading/skeleton).

## When to use

- Short opaque waits where layout does not need reserved structure
- Busy chrome inside a button or chip (prefer `loading` / addon patterns the control already owns)
- A panel status row with muted helper copy under the indicator

## When not to use

- You need the page structure to stay put while content loads → [Skeleton](/components/loading/skeleton)
- Upload, export, or sync progress with a track metaphor → [LinearProgress](/components/loading/linear-progress)
- Nesting a second Spinner inside Button / IconButton when `loading` already injects one

## Related

## Common examples

### Centered status

A centered status region with muted supporting text is the usual pattern when a panel is fetching. Keep the Spinner decorative (`aria-hidden`) and let the visible copy name the wait.

<PreviewSlot label="Spinner preview" />

```tsx
import { Spinner, Stack, Text } from '@viraui/react';

<Stack rowGap="s" hAlign="center" role="status" vPadding="l">
  <Spinner aria-hidden size="l" variant="bars" />
  <Text tone="muted" size="s" align="center">
    Fetching latest data
  </Text>
</Stack>
```
