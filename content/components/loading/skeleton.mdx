---
title: Skeleton
description: Loading placeholders — fixed blocks or Skeleton.Overlay shaped to the content they replace.
---

`Skeleton` paints neutral placeholder blocks while real content is still fetching. Size free-form rows with explicit `width` and `height` (or let flex stretch them); avatar circles use `radius="full"` on square dimensions.

When the final layout already exists in markup, wrap that node in `Skeleton.Overlay`. The overlay measures the child and paints a pulse mask on top, so placeholders stay aligned when copy wraps or media aspect ratios differ. Theme [radius](/foundation/radius) rounds corners like other surfaces.

Mark the hosting region `aria-busy` (and an accessible name when a whole card loads) so assistive tech knows content is provisional — Skeleton roots stay decorative. The pulse respects `prefers-reduced-motion`; set `animate={false}` when a static block reads better. For an Overlay reveal wipe, put `view-transition-name: skeleton-overlay` on a CSS class wrapping the skeleton and loaded content.

---

## When to use

- Content structure is known and you want layout to stay stable while data loads
- Card, list, or profile chrome that should not collapse into a blank hole
- Real Title / Text / media already in the tree and the pulse should match their box (`Skeleton.Overlay`)

## When not to use

- A short opaque wait with no layout to reserve → [Spinner](/components/loading/spinner)
- A task with known or indeterminate percent along a track → [LinearProgress](/components/loading/linear-progress)
- Loading should give hint about the current loading status → [Shimmer](/components/typography/shimmer) on Text / Title

## Related

## Common examples

### Avatar and text lines

A profile header before data resolves: circular avatar beside two text lines inside a bordered card. The Surface carries `aria-busy` and an accessible name; Skeleton roots stay decorative.

<Example preview={<SkeletonAvatarTextDemo />}>

```tsx
import { Skeleton, Stack, Surface } from '@viraui/react';

<Surface
  aria-busy="true"
  aria-label="Loading profile"
  border="all"
  radius="l"
  role="region"
  hPadding="m"
  vPadding="m"
>
  <Stack direction="row" columnGap="m" vAlign="center">
    <Skeleton radius="full" height="3rem" width="3rem" />
    <Stack expandChildren rowGap="s">
      <Skeleton height="1rem" width="8rem" />
      <Skeleton height="0.875rem" width="5rem" />
    </Stack>
  </Stack>
</Surface>
```

</Example>

### Overlay on real content

Wrap the real Title and Text the card will show. `Skeleton.Overlay` sizes the pulse to those children so the loaded layout does not jump.

<Example preview={<SkeletonOverlayDemo />}>

```tsx
import { Skeleton, Stack, Surface, Text, Title } from '@viraui/react';

<Surface
  aria-busy="true"
  aria-label="Loading workspace card"
  border="all"
  radius="l"
  role="region"
>
  <Stack expandChildren hPadding="l" rowGap="m" vPadding="l">
    <Skeleton.Overlay>
      <Title />
    </Skeleton.Overlay>
    <Skeleton.Overlay>
      <Text size="s" tone="muted" />
    </Skeleton.Overlay>
  </Stack>
</Surface>
```

</Example>

### Equal-width actions

Stack `expandChildren` on a row of Skeletons so action placeholders share width like a dual Button footer — no flex CSS.

<Example preview={<SkeletonEqualActionsDemo />}>

```tsx
import { Skeleton, Stack, Surface } from '@viraui/react';

<Surface
  aria-busy="true"
  aria-label="Loading actions"
  border="all"
  radius="l"
  role="region"
  hPadding="m"
  vPadding="m"
>
  <Stack columnGap="s" direction="row" expandChildren>
    <Skeleton height="2.5rem" radius="l" width="100%" />
    <Skeleton height="2.5rem" radius="l" width="100%" />
  </Stack>
</Surface>
```

</Example>
