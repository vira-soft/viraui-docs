Button is the default **labeled** action control. Visible text children name what happens when you activate it; the control stays a real button for keyboard and assistive tech. Reach for [IconButton](/components/actions/icon-button) when there is no visible label.

When the affordance should navigate — in-app route or external URL — use **ButtonLink** instead. It shares the same visual chrome (`size`, `variant`, `addon`, `pill`, `loading`) but renders a native `<a>` (or a framework `Link` via `render`). Do not force `render={<a />}` on Button; Base UI keeps button semantics there.

Variants follow intent, not decoration. Use the filled primary for the one commit action on a surface, secondary for cancel or peer choices, flat when the control should sit quietly in chrome, and destructive only when the action removes or cannot be undone. Size steps denser or roomier rows; `pill` rounds the control into a capsule when that shape fits the layout.

Optional `addon` slots accept a leading or trailing icon (or a small Chip / Avatar). Button CSS sizes SVG descendants — glyph size comes from the button, not per-icon CSS. When `loading` is on, the control keeps its width, sets `aria-busy`, and shows a decorative Spinner over the label. On Button, loading also blocks activation; on ButtonLink there is no `disabled` prop — loading sets `aria-disabled` / `aria-busy` while the link stays activatable.

## Common examples

### Variants

Pick the variant from what the action means on that surface. A bare Button is already primary; reach for another variant when the action is not the commit.

<ButtonVariantsDemo />

```tsx
import { Button, Stack } from '@viraui/react';

<Stack direction="row" columnGap="m" wrap>
  <Button>Save</Button>
  <Button variant="secondary">Cancel</Button>
  <Button variant="flat">Learn more</Button>
  <Button variant="destructive">Delete</Button>
</Stack>
```

Prefer one primary per region. Pair it with secondary cancel rather than two competing filled actions.

### Icons beside the label

Pass icons through `addon`, not as lone children. Leading is the default; set `addonPosition="end"` when the glyph trails the label. `pill` rounds the control into a capsule when that shape fits the row.

<ButtonAddonDemo />

```tsx
import { Download, FloppyDisk, Trash } from '@phosphor-icons/react';
import { Button, Stack } from '@viraui/react';

<Stack direction="row" columnGap="m" wrap>
  <Button addon={<Download />}>Download</Button>
  <Button addon={<FloppyDisk />} addonPosition="end" variant="secondary">
    Save draft
  </Button>
  <Button addon={<Trash />} pill variant="destructive">
    Delete
  </Button>
</Stack>
```

If the control has no visible text, switch to [IconButton](/components/actions/icon-button) with an accessible name — do not empty Button children and hope the icon is enough.

### Loading

Turn on `loading` while the request runs. Width stays stable so the layout does not jump when the Spinner appears; the Spinner itself stays decorative because `aria-busy` already marks the control.

<ButtonLoadingDemo />

```tsx
import { Button, Stack } from '@viraui/react';

<Stack direction="row" columnGap="m" wrap>
  <Button loading>Publishing…</Button>
  <Button loading variant="secondary">
    Saving
  </Button>
</Stack>
```

Keep the same label text during the wait (or a short “…”) so the announced name stays continuous. On Button, loading also disables activation until you clear the flag.

### Action rows

Footer and dialog strips are Stack rows of Buttons — gap and alignment live on the Stack, not on per-button width CSS. Here the three actions share the strip equally: `fullWidth` fills the parent, `expandChildren` grows each Button on the main axis.

<ButtonActionRowDemo />

```tsx
import { FloppyDisk } from '@phosphor-icons/react';
import { Button, Stack } from '@viraui/react';

<Stack direction="row" columnGap="m" expandChildren fullWidth>
  <Button variant="secondary">Cancel</Button>
  <Button variant="destructive">Delete</Button>
  <Button addon={<FloppyDisk />}>Save</Button>
</Stack>
```

### As a link

Use ButtonLink when activation should navigate. Same chrome as Button; different element — a native `<a>`, or a framework `Link` via `render`.

<ButtonLinkDemo />

```tsx
import { ArrowRight, ArrowSquareOut, BookOpen } from '@phosphor-icons/react';
import { ButtonLink, Stack } from '@viraui/react';

<Stack direction="row" columnGap="m" wrap>
  <ButtonLink href="/docs" addon={<BookOpen />}>
    Documentation
  </ButtonLink>
  <ButtonLink
    href="/next"
    addon={<ArrowRight />}
    addonPosition="end"
    variant="secondary"
  >
    Continue
  </ButtonLink>
  <ButtonLink
    href="https://docs.viraui.dev"
    addon={<ArrowSquareOut />}
    addonPosition="end"
    rel="noreferrer"
    target="_blank"
    variant="flat"
  >
    External docs
  </ButtonLink>
</Stack>
```

Pass `href` for native or external URLs (`target` / `rel` when needed). Trailing addons suit “continue” and external destinations.

```tsx
import Link from 'next/link';
import { ButtonLink } from '@viraui/react';

<ButtonLink render={<Link href="/docs" />}>Documentation</ButtonLink>
```

Pass `render` for in-app framework routing. Icon-only navigation belongs on [IconButton](/components/actions/icon-button) (`IconButtonLink`).
